### Fixed

- **The proofer's case generators read the round records of every release since 0.23.0 (#1150).** `evals/scripts/replay_targets.py` builds a replay case from a review round this repository already ran. `evals/scripts/seed_defects.py` builds a seeded case from a shipped work item's round 1. Both read round records only at `seal/specs/<item>/rounds/`, the layout before 0.23.0, and every release since keeps them at `seal/threads/<id>/trail/rounds/`. So `replay_targets.py --list` over the last two release tags printed nothing and exited 0. `seed_defects.py --list` left out every shipped commit, as one that adds no work item's `routing.md`. Both generators now read either layout, from one statement of the two in `replay_targets.py`. The next round's record, `routing.md` at the reviewed commit, and the report path a case's prompt and graders name are each taken from the layout of the record they derive from.

- **A round record written in `seal` blocks, as every record since 0.27.0 is, is read as one (#1150).** The replay generator read such a record as a table of the records before 0.22.0. It left each one out as `Target SHA (none) does not resolve`, which is false, because the record names its commit in its round block. A record that holds a `seal` block is now judged and read, whether the parser reads any of its blocks or refuses every one, by the `chain_check.py` of the commit that last wrote it, through that commit's `round_of` and `round_read`. The reviewed commit and its base come from the round block's `target:` value, and a truth comes from a finding block's `location:` value whose close block reads `fixed`. The next round confirms the truth in a confirmation block. A record that check refuses is left out with the check's refusal. Over v0.27.0 and v0.26.0, none of the 10 records in blocks is now left out with the false reason, and one of them gives a target. The eight committed proofer cases regenerate byte for byte as they did before.

- **A generator run that reads no round record says so and exits 1 (#1150).** It used to print nothing and exit 0, which reads as "nothing to do". `replay_targets.py` now prints one line on stderr. The line names both layouts and the tags it read. `seed_defects.py` does the same where no commit it read holds a round 1 record, after each commit's `left out:` line. With `--case`, both generators read a name only in a case's form, `replay-<the work item's epoch>-r<the round>` or `seeded-<a shipped commit's first eight hex digits>`, and answer a name the same way. Each name that no written case answers, or with `--list` no listed line, is named on stderr with its reason, and the run exits 1. For a name of another form, such as a case's name without its prefix, the reason is the form a case's name takes. Otherwise, in `replay_targets.py`, the reason is the one the round was left out with, or that no record of its work item, or of that round, was read. In `seed_defects.py`, it is the one the shipped commit was left out with, or that no shipped commit read has the name's digits as its first eight. A run no longer exits 1 for a name given twice whose case it wrote, which it used to do saying nothing; an unanswered name given twice is still named twice (#1228). No script in the tree reads either generator's exit code.
