## Scope

In:

1. **One statement of the two record layouts, in `replay_targets.py`, which `seed_defects.py` imports.** Each layout gives the path of a round record, the directory its records stand in, and the path of its work item's `routing.md`. The two layouts are `seal/specs/<item>/rounds/round-<n>.md` with `seal/specs/<item>/routing.md`, and `seal/threads/<id>/trail/rounds/round-<n>.md` with `seal/threads/<id>/routing.md`.
2. **`replay_targets.py` reads round records in both layouts, in the working tree and at each tag it reads.** Each record carries the path it was read at. The next round's record, `routing.md` at the target, `written_at` and the report path in the case's prompt and graders all take their path from the layout of the record they derive from. A case cut from a 0.22.x record keeps its `seal/specs/…` report path, and a case cut from a thread-layout record writes its report at `seal/threads/<id>/trail/rounds/round-<n>.md`.
3. **`seed_defects.py` finds the work item a shipped commit adds in either layout**, by the `routing.md` it adds, and reads that item's round 1 and round 2 records in the same layout.
4. **Where no record is read, the generator says so and exits 1.** `replay_targets.py` prints one line on stderr and exits 1 where neither layout holds a round record in the working tree or at any tag it read. The line names both layouts and the tags. With `--case`, each name that no written or listed case answers is named on stderr with its reason, the reason `round_target` gave or that no record of its work item was read, and the run exits 1, `--list` included (round 1's finding 1, 32584024). `seed_defects.py` prints one line on stderr and exits 1 where no commit it read holds a round 1 record in either layout, and it still prints the `left out:` line of each commit. With `--case`, it names on stderr each name that no shipped commit answers and exits 1, `--list` included, as `replay_targets.py` does, so the two generators answer a name alike. A name is read as a case only where it matches its module's `CASE_NAME` whole, `seeded-` and a commit's first eight lower-case hex digits, or `replay-<item digits>-r<round>`; a name of another form is answered on stderr with the form it must take, and the run exits 1. A `--case` run no longer compares the number of cases written with the number of names given: it exits 1 where a name is unanswered, and `seed_defects.py` also where no commit it read holds a round 1 record (round 3's finding 1, 9237e34b).
5. **A round record in `seal` blocks is read as one.** A record holding a `seal` block of a round record's kinds, accepted or refused by the parser, is judged in blocks (round 1's finding 2, 32584024); one the parser accepts is read through `round_read` and `round_of` of the `chain_check.py` of the commit that last wrote it. Its `target:` value and each finding's `location:` value come from the parsed blocks. Its next round's `confirms:` references come from `round_of`. It is never read as a table record. A labelled record and a table record are read as they are today.
6. **The module docstrings and comments state what the scripts now read.** This covers `replay_targets.py`'s description of the two shapes and of the layout it reads, its `Exit codes` line, and the comment above `TARGET_LABEL`, which says every record a replay reads stands in labelled lines. It covers `seed_defects.py`'s module docstring and its `Exit codes` line. It covers the comment above `tests/censuses.py#KEPT_FILES`, which says the generators read round records at the 0.22.x layout. Each new stderr line is pinned by a test (contract rule 14).

Out, each with its reason:

- **Rewriting a committed case, or any scaffold, into the thread layout.** A scaffold checks out the reviewed commit as it stands. Moving `seal/specs/` in that tree would put the move into the `base..target` diff the proofer reviews (`frame/plan.md` A3). With scope item 2, a case cut from a 0.23.0-or-later record already rebuilds a thread-layout tree that the current plugin reads as its root (`## Grounding`, the `optin.py#MARKER` row).
- **Replacing the committed 0.22.x cases with cases cut from thread-layout records.** This is a decision about which cases the proofer suite measures, and it changes no line of the reader (`frame/questions.md` Q2).
- **A base that resolves for a round whose `target:` names a release branch deleted since.** In the v0.27.0 and v0.26.0 probe, 10 records are left out as `the target line names no base that resolves`. `replay_targets.py#targets` passes no `landed` commit to `round_target`, in either layout. This is a separate defect with its own fix, and it does not stop either layout's records being read. The orchestrator files it.
- **Naming as not read the files under `seal/specs/` that are named like a split record, such as `round-1-report.md`.** 620 such paths stand at v0.9.1 to v0.22.3 (executed: `git ls-tree` over every release tag), and none stands at any later tag. `--case` reads every tag, so printing them would add hundreds of lines to every run. The core's rule on naming what a script did not read binds a script that holds a gate (`skills/core/SKILL.md` *The rule a mechanism is kept against*). Neither generator holds one.
- **`.github/scripts/release_seal.py#chain_counts`,** the other reader `docs/the-review-record.md` names. It reads one release's records with the tree's own check, and the ticket does not name it.
- **How a truth is cut from a `location:` value that names several paths.** The value is read as it is today: `truth_option` takes the first backticked path. Changing that changes the truths of new cases, not which records are read.

## Data & interfaces

- `evals/scripts/replay_targets.py#RECORD` (one regex, `seal/specs/…/rounds/`) becomes one statement of the two layouts (scope item 1). `seed_defects.py#SPEC` and the rounds path at `seed_defects.py:204` read from that statement.
- `replay_targets.py#records` returns each record with the path it was read at, so `round_target` stops composing `seal/specs/{item}/rounds/round-{n}.md` at `:645` and `:674` and `seal/specs/{item}/routing.md` at `:669`. `prompt` at `:746` and `graders` at `:778` take the report path from the target, and `seed_defects.py#prompt` at `:327` and `#graders` at `:348` do the same. The crafter chooses the return shape. `tests/evals/test_replay_targets.py#Test_module::test_records_read_only_the_named_items` pins the present one and is rewritten with it.
- A record's shape is decided in this order. A record whose parsed blocks hold a round block is a block record. Otherwise a record with a `target:` line among its readable lines is labelled (`labelled`). Otherwise it is a table record. Shape detection uses this tree's parser. A record is judged by the parser of the commit that wrote it, through `checks_at`, whose `CHECK_FILES` already copies `hooks/lib/fields.py`.
- `confirmed` reads a block record's `confirms:` references through `round_of`, as it reads a labelled one.
- Exit codes: `0` written or listed. `1` covers fewer targets than `--count`, a named case not written, and, new here, no round record in either layout. `2` means the arguments were unusable. No script in the tree reads either generator's exit code. `noninferiority.py` and `rule_cases.py` import `record_reader`, `truths_with`, `md` and `html` and call no `main` (executed: `grep -o 'rt\.[a-zA-Z_]*'`).
