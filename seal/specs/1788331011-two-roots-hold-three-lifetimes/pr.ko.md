## 무엇이 달라지는가

작업 항목의 문서는 `specs/<id>/` 에, 리뷰 기록도 그 안에, 근거 대조표(스펙
조항과 코드 좌표를 짝지어 둔 표)는 `.specseal/` 에 있었습니다. 수명이 다른
세 가지가 두 디렉터리에 나뉘어 있던 셈입니다. 문서는 작업 항목을 정리할 때
사라지고, 리뷰 기록은 PR 과 함께 끝나며, 대조표의 행은 둘보다 오래 남습니다.
게다가 그 두 디렉터리 중 하나가 곧 옵트인이었으므로, 라우팅 선언 하나를 쓴
저장소는 자기도 모르게 게이트 넷을 켜게 됐고, 모든 게이트·검사기·릴리스
스크립트가 경로 접두어 둘을 들고 다녔습니다.

이제 플러그인이 관리하는 디렉터리 `seal/` 하나에 수명별로 놓이고, 그 디렉터리가
있는 것이 곧 옵트인입니다.

1. **`seal/specs/<id>/` 가 작업 항목 전체를 담습니다.** 리뷰 라운드는 그 아래
   `rounds/` 에 들어갑니다. 대조표는 `seal/ledger.md` 와 `seal/ledger/<id>.md`
   입니다. `seal/follow-up.md` 와 `seal/parity.md` 는 한 단계 위로 올라왔을 뿐
   그대로입니다. 저장소 루트나 git 디렉터리 아래에 `seal/` 이 있으면 옵트인이고,
   `.specseal/` 은 더 이상 아무것도 켜지 않습니다. 일회용 저장소라고 표시하려면
   커밋할 수 없는 파일 `.git/specseal-scratch` 를 둡니다.
2. **옛 배치의 저장소는 업데이트 뒤 첫 세션 시작 때 한 번 옮겨집니다.** 모든
   이동은 스테이징된 `git mv` 이고, 옮겨진 파일을 인용하는 대조표 행은 해시를
   건드리지 않은 채 경로만 바뀝니다. 무엇을 옮겼는지 한 줄이 나오고, 사람은
   diff 를 보고 커밋합니다. 옛 디렉터리에 커밋하지 않은 작업이 있으면 먼저
   커밋하라는 한 줄과 함께 거부합니다. 중간에 멈춘 이동은 어디까지 옮겼는지
   말하고 다음 세션 시작에서 이어집니다. `.specseal/` 이 심볼릭 링크이거나,
   `seal` 이 이미 파일이거나, 옮길 자리에 같은 파일이 이미 있으면 각각 손으로
   할 일을 적은 한 줄과 함께 거부하고, 어느 경우에도 완료 표시를 남기지
   않습니다.
3. **모든 게이트·검사기·릴리스 스크립트가 새 경로를 읽습니다.** `CHANGELOG.md`
   와 대조표의 `<!-- specs/<id> -->` 표시는 그대로입니다. 작업 항목을 가리키는
   이름이고 하위 디렉터리 이름은 여전히 `specs/` 이기 때문입니다. 체인 검사는
   PR 이 이름만 바꾼 라우팅 선언을 더 이상 판정하지 않으므로, 기존 작업 항목을
   전부 옮기는 이 PR 이 자기 릴리스를 깨뜨리지 않습니다.
4. **README·스킬·에이전트·템플릿·워크플로가 전부 `seal/` 로 말합니다.** 역사를
   설명하려고 남긴 몇 문장 외에 옛 이름을 적은 문서가 있으면 테스트가
   거부합니다.

## 리뷰에서 나온 것

네 라운드를 돌았고 마지막 라운드는 고칠 것을 열지 않았습니다. 첫 라운드는
`.specseal/` 바로 아래 무시된 파일 하나(macOS 의 `.DS_Store`)만 있어도 이동이
매번 같은 자리에서 멈추고, 게이트는 켜진 채 라우팅 선언은 옛 자리에 남는 상태를
찾았습니다. 이제 이동 단위는 git 이 추적하는 것으로 정합니다. 같은 라운드에서
`seal` 이 파일일 때 훅이 소리 없이 죽는 것, 이미 있는 목적지에 대해 오지 않을
"다음에 이어집니다" 를 약속하는 것, `specs/` 아래 SpecSeal 것이 아닌 항목을
인용한 행이 없는 경로로 바뀌는 것도 나왔습니다. 검증 라운드들은 첫 라운드가 읽기만
했던 심볼릭 링크 두 경우를 실행해 보고, 그 읽기가 틀렸음을 찾았습니다. 훅은 거기서
실패하지 않고 옮길 수 있는 것만 옮긴 뒤 완료 표시를 남기고 있었습니다. 이제는
두 링크 모두 직접 옮기는 절을 가리키는 한 줄과 함께 거부합니다. 라운드에 걸쳐 회귀 테스트 열한 개를 빨간불부터 확인하고 심었습니다.

## 결정을 남겨 둔 것

`questions.md` 의 Q1–Q8 은 기본값으로 진행했습니다. 이름은 설계 기록의 추천대로
(`seal/`, `seal/specs/`, `seal/ledger.md`), changelog 와 대조표 표시는 그대로,
옵트인은 두 자리를 지금부터 읽고, 일회용 표시는 `.git/` 아래의 커밋할 수 없는
파일로 두고, 옮겨진 README 는 템플릿으로 덮어쓰고, `implement` 스킬의 첫 설정은
이번 릴리스에 모드를 묻지 않고, 라운드 기록을 인용하는 대조표 행 하나는 `settle`
항목을 적은 메모와 함께 경로만 바꾸고, 이동이 거부된 채 커밋되지 않은 저장소는
저장소당 한 번만 조용히 넘어가며 조용한 게이트가 뒤를 받칩니다.

## 운영에 영향을 주는 것

이 플러그인을 쓰는 모든 저장소가 업데이트 뒤 첫 세션 시작에서 옮겨지고, 사람은
스테이징된 diff 를 보고 커밋합니다. Claude Code 세션 안에서 그 커밋은 어느 작업
항목에도 속하지 않으므로 `: '[no-review]'; git commit …` 으로 게이트를 한 번
비켜 갑니다(`seal/parity.md` 가 있으면 `[no-parity]` 도 옆에). README 에 그렇게
적었습니다. `templates/map.md` 와 `templates/specseal-README.md` 는
`templates/ledger.md` 와 `templates/seal-README.md` 가 됐습니다. 새 의존성은
없습니다.
