# 규칙대로 썼는데도 읽기 어려웠고, 파일에서 세 가지가 그 이유입니다

<!-- PR 본문의 한국어판. 영어 본문이 정본이고 이 파일이 번역입니다. -->

`writing-style` 을 따라 쓴 PR 본문이 *"이게 writing-style 을 적용한 거라기엔
너무 읽기 어렵다"* 는 말과 함께 돌아왔습니다. 규칙을 더 세게 쓰는 것은 답이
아닙니다. 규칙은 이미 거기 있었고 발동하지 않았습니다.

## 무엇이 달라지나

### ① 문서 유형별 절이 전부인 것처럼 보였습니다

PR 본문을 쓰려고 파일을 연 사람은 「PR 본문에만 해당하는 것」부터 읽습니다.
거기 표가 있으니 그게 전부인 줄 압니다. *"문장 규칙도 같이 적용된다"* 는 줄은
이백 줄 위에 있고, 그 사람은 거기를 안 갑니다.

이제 각 절 머리에 그 줄이 다시 있습니다. **아래는 문장 규칙에 더해지는
것이지 대신하는 것이 아니다.**

### ② 자기 은어를 알아차릴 방법이 없었습니다

예시가 전부 남의 도메인 말이라 남의 어휘로 읽혔습니다. 그런데 한 시간 전에
코드에서 배운 단어는 이미 평범한 말처럼 느껴집니다. 그래서 규칙을 읽고도
그대로 씁니다.

판별법을 넣었습니다. **이 저장소에서 처음 배운 단어면 은어다.** 코드에서든
정책 문서에서든 마찬가지입니다.

그리고 실제로 새는 것은 낱말이 아니라 한 부류라는 것도 적었습니다 — 추상
한자어 명사화입니다. 승계·원천·구간·격자·굳음·창구 같은 말이고, 목록으로는 다
못 잡습니다.

### ③ 사용자와의 대화가 아예 빠져 있었습니다

문서가 다루는 글이 넷이었습니다. 리뷰 코멘트, PR 본문, 조사 리포트, 다른 팀에
답하는 코멘트. **터미널에서 사용자에게 답하는 글은 없었습니다. 그런데 이게
제일 자주 쓰는 글입니다.**

그래서 PR 본문 문체가 그대로 대화로 넘어옵니다. 대화는 다른 글이라는 말이
어디에도 없으니까요. 실제로 이 세션에서 그렇게 됐고, 사용자가 *"말 너무
어렵게 쓴다"* 고 했습니다.

이제 표에 줄이 하나 늘고, 자기 절이 생겼습니다. 결론 먼저, 짧은 문장, 이
저장소가 만든 말 금지, 표는 숫자 견줄 때만.

| | 이전 | 이후 |
|---|---|---|
| PR 본문을 쓰려고 파일을 연 사람 | 그 절의 표만 적용합니다 | 절 머리에서 문장 규칙으로 돌려보냅니다 |
| 오늘 코드에서 배운 단어를 쓰려 할 때 | 평범한 말로 느껴져서 그대로 씁니다 | "여기서 처음 배웠나" 한 번 물어봅니다 |
| 사용자에게 답할 때 | 해당하는 절이 없어서 PR 본문 문체를 씁니다 | 자기 절이 있습니다 |
| 플러그인을 설치한 사람 | — | smith·warden 이 이 문서를 따르므로 두 에이전트의 글이 바뀝니다 |

## 되돌리는 규칙은 없습니다

전부 추가입니다. 기존 규칙을 뒤집은 곳이 없어서, 예전 규칙대로 쓴 글이 이
변경으로 틀린 글이 되지는 않습니다.
