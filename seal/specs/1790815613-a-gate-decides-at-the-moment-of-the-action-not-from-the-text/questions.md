## Judgments the ticket left open that the tree answered

Each is decided in `spec.md` §*What the tree answered, so nobody reopens it*,
with its grounds; this list exists so a reader can tell a question that was
decided from one that was never met.

1. Whether a further patch to the text reading is a candidate — no (the
   owner's stop of 2026-09-30; `plan.md` row P).
2. What invariant replaces "no shape the base stopped reads silent" — "no
   commit, switch or creation that reaches an opted-in repository goes
   unjudged" (spec, 2).
3. Which git hooks exist for which action, and what each can and cannot
   refuse — from `git help githooks` on 2.50.1 (spec, 3).
4. How a hook learns the session id and that a Claude session is running —
   the harness's environment variables, measured in this framer's own Bash
   child, with the lease's pid as the second route (spec, 4).
5. That the automation press and the routing declaration need no command
   text — `automation_answered` by session id, `declared` by the real branch
   (spec, 5 and 6).
6. What the recorded run cost, counted from the transcripts rather than
   recalled (spec, 7).
7. That the ticket's "advisory PreToolUse fast path" is not built (spec, 8).
8. Why a stub embeds the installed path and one install covers a clone
   (spec, 9 and 10).
9. That tokens may stay a text read and nothing else may (spec, 11).
10. #678 refused and #686 answered by the design, with the floor's exception
    (spec §*The two open issues*).
11. The two #689 whites close by deletion (spec, 13).

What survives that is below. A row says which of the three answerers it

**`Who can answer` takes one of three values and nothing else.** A person
for a value somebody has to be accountable for — the only kind that blocks
the build. A measurement for what a probe, a command or a count settles.
The work for what the phase that meets it will know.

**The framer opens rows and does not own their answers.** The `Status`
column is ticked by whoever answered. Of the four person rows, none changes
what phase 1 and 2 build; P1 and P4 change what phase 2 and 5 fall back to,
P2 changes one branch of phase 3's stub, and P3 changes whether phase 4 and
5 build the translator. The build can start on the defaults and the
spawning session can put the four rows to the owner in one call.

Answered rows feed back into docs/ (policy clause or open-questions section)
before this directory's work merges.
