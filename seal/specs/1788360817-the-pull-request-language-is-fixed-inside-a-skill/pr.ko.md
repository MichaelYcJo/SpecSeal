# 저장소가 자기 PR 언어를 말할 수 없었습니다

<!-- seal/specs/1788360817-the-pull-request-language-is-fixed-inside-a-skill/pr.ko.md
— PR 본문의 한글판. 영어 본문이 정본이고 이 파일은 사람이 읽기 위한 거울입니다. -->

## 무엇이 달라지는가

`commit-pr-convention` 스킬은 커밋 제목과 본문, PR 제목과 본문을 모두 영어로
쓰라고 요구했습니다. 한 사람의 관습이 모두의 규칙이 된 것이고, 팀이 한국어로
쓰는 저장소는 그렇다고 말할 방법이 없었습니다.

이제 저장소가 자기 루트의 `config.md` 한 행으로 말합니다.

```
| Item | Value |
|---|---|
| Pull request language | Korean |
```

스킬은 넷 중 무엇을 쓰기 전에 그 행을 읽습니다. **행이 없거나 파일이 없으면
영어**이므로, 아무 말도 하지 않는 저장소는 지금까지와 똑같이 동작합니다. 이
저장소도 파일을 만들지 않았습니다.

행 하나가 넷을 다 답하는 이유는 squash 때문입니다. 기능 브랜치가 squash 되면
커밋 본문이 곧 PR 본문이 되므로, 넷이 서로 다른 언어일 수 없습니다.

**행이 닿지 않는 것 셋**을 스킬과 템플릿 양쪽에 적었습니다. 설정 파일을 쓰는
사람은 템플릿을 읽고 스킬은 읽지 않기 때문입니다.

- **prefix 는 번역하지 않습니다.** `feat:` 은 로그를 훑는 사람과 그것을
  파싱하는 도구가 함께 읽는 것이라, `기능:` 은 둘 다에게 아무것도 가르치지
  않습니다.
- **브랜치 이름은 ASCII 로 남습니다.** 셸에 타이핑되고 URL 에 붙여넣어지는
  이름입니다.
- **응답 언어는 이 파일에 없습니다.** 한 저장소의 두 사람이 응답 언어는 서로
  다르게, PR 언어는 같게 원할 수 있습니다.

**미러 파일은 자기 언어로 이름 붙입니다.** 영어 저장소는 `pr.ko.md`, 한국어
저장소는 `pr.en.md` 입니다. 그래서 이 저장소의 기존 미러들은 새 규칙에서도
그대로 맞고, 하나도 옮기지 않았습니다. 로컬 모드에서는 루트가 git 디렉터리
아래라 커밋할 수 없으므로, 미러는 PR 이 이미 건드리는 문서 옆에 둡니다.

## 리뷰에서 나온 것

여섯 라운드를 돌았고, 상한(셋)을 셋 넘겼습니다. 넘긴 이유는 라운드마다
기록에 적혀 있습니다. 마지막 라운드는 코드가 하는 일에서 결함을 찾지
못했습니다.

무거운 것 셋입니다.

- **적법한 설정 파일이 검사를 깨뜨렸습니다.** 미러 검사가 행의 값으로 세 칸짜리
  사전을 색인해서, 템플릿이 명시적으로 허용하는 네 번째 언어를 적으면 단언이
  아니라 예외가 났습니다.
- **설정 파일의 자리는 두 갈래로 풀고 미러의 자리는 한 줄로 박아 놨습니다.**
  로컬 모드에서 그 경로는 아무것도 커밋되지 않는 자리인데, 그게 바로 스킬이
  미러를 저장소 안에 두라고 한 이유 셋을 한꺼번에 지웁니다.
- **한국어 이름의 템플릿을 검사가 거부하고 있었습니다.** `git ls-files` 가
  비ASCII 경로를 기본값으로 이스케이프해서, 산문이 그 파일을 이름 부르고
  있는데도 "아무 문서도 이름 부르지 않는 템플릿" 으로 보고했습니다. 영어가
  아닌 언어로 쓰는 저장소를 위한 작업 항목에서 나온 결함입니다.

## 이 실행이 스스로 측정한 것

라운드 2·3·4 가 **직전 라운드의 수정이 만든 유닛 안에서** 다음 결함을
찾았습니다. 산문을 고치면 그것을 고정하는 검사 코드를 새로 쓰고, 그 코드는
아무도 리뷰하지 않은 채 실리고, 다음 라운드가 거기서 결함을 찾습니다. 결함은
매번 작아지는데 멈추지 않습니다. 그것을 만들어 내는 표면이 수정할 때마다
자라기 때문입니다.

그래서 라운드 4 이후의 수정 패스에는 **새 유닛을 만들지 말라**는 조건을
걸었고, 두 패스 연속 지켜졌습니다(함수 46 개, 상수 11 개, 테스트 37 개
불변). 그러자 라운드 5 가 찾은 것은 새 결함이 아니라 **미완성 수정**이었습니다.
같은 모양의 형제 호출 둘 중 하나만 고쳐져 있었습니다.

이 관찰과 그것이 무엇을 바꿔야 하는지는 이슈 #97 과 #89 에 있습니다.

## 남겨 둔 것

- **이슈 #98** — 주석과 대조표 행 셋이 `-z` 만 git 의 경로 이스케이프를
  끈다고 적었는데, `core.quotePath=false` 도 끕니다. 런타임 영향은 없습니다.
  `-z` 가 남아야 하는 진짜 이유는 제어문자까지 끄고, NUL 이 파일 이름에 들어갈
  수 없는 유일한 구분자이기 때문입니다.
- **`tests-todo.md` 14 행이 "부분적으로 심음"** 입니다. 심은 단언이 목록
  생성 코드를 지나가지 않아서, 그 절반은 고정되지 않았습니다. 나머지를 닫으려면
  새 유닛이 필요하고, 그것이 위의 조건이 금지한 유일한 것입니다. 무엇을
  고정하고 무엇을 안 하는지 세 곳에 적었습니다.
- **`docs/one-root-by-lifetime.md:449-450`** 이 아직 `pr.ko.md` 를 소유자의
  개인 설정이라고 부릅니다. 이 변경은 그것을 저장소 설정의 함수로 만들었습니다.
  이슈 #82 가 설계 기록을 범위 밖으로 두었으므로 열어 둡니다.

## 이 브랜치가 함께 싣는 것

`docs/flow.md` 의 두 줄은 이 작업 항목의 것이 아니라 릴리스 계획 결정입니다.
sealer 를 0.6.0 으로 옮긴 것과, 릴리스 가드의 사각(이슈 #96)을 릴리스 줄 앞에
넣은 것입니다. `release/v0.5.0` 은 직접 푸시를 받지 않고, 한 줄짜리 계획 변경이
자기 PR 을 가질 만큼은 아니라 여기 탔습니다.
