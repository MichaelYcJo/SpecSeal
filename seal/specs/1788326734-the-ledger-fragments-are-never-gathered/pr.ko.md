## 무엇이 달라지는가

작업 항목마다 근거 대조표(스펙 조항과 코드 좌표를 짝지어 둔 표)의 행을 자기
조각 파일 `.specseal/map/<id>.md` 에 씁니다. 두 브랜치가 한 파일 앞에 줄 서지
않게 하려는 배치였는데, 그 조각을 다시 `map.md` 로 접는 단계가 없어서 파일이
작업 항목마다 하나씩 영원히 남고 PR 을 올릴 때마다 그 디렉터리에 손이 갔습니다.

릴리스 준비 단계에 `fold_ledger.py` 가 생깁니다. changelog 조각을 모으는
`gather_changelog.py` 와 같은 모양(`--version` · `--dry-run` · `--check`)이고,
같은 커밋에서 둘을 함께 돌립니다.

1. **조각을 전부 `map.md` 로 옮기고 지웁니다.** 릴리스 제목과 작업 항목 제목
   아래에 행을 한 글자도 바꾸지 않고 옮기고, 대조표가 디스크에 쓰인 뒤에야
   조각 파일을 지웁니다. 옮긴 항목마다 CHANGELOG 와 같은 HTML 주석 표시를
   남겨서, 두 번 접히지 않고 나중에 출처를 되짚을 수 있습니다.
2. **확인된 사실이 대조표 밖에 남아 있으면 거부합니다.** 리뷰어가
   `specs/<id>/evidence-todo.md` 에 적어 둔 사실이 아직 대조표로 옮겨지지
   않았으면(열린 행이 있으면), 파일 이름을 대고 아무것도 쓰지 않은 채
   멈춥니다. 열린 행의 규칙은 사람이 눈으로도 적용할 수 있게 스펙에
   네 단계로 적었습니다. `drained` 줄이 있으면 닫힌 파일, 없으면 ✅ 없는 행이
   열린 행입니다.
3. **`main` 으로 가는 PR 에서 hygiene 워크플로가 `--check` 를 돌립니다.**
   남은 조각이나 열린 행이 있으면 릴리스 PR 이 멈춥니다. 릴리스 브랜치로 가는
   PR 에서는 돌지 않습니다. 거기서는 접히지 않은 조각이 정상이기 때문입니다.

"조각은 절대 모으지 않는다" 고 적혀 있던 문서 열두 곳이 새 규칙으로
바뀌었고, 그 문장이 다시 나타나면 테스트가 잡습니다.

## 리뷰에서 나온 것

라운드 셋을 돌았고, 마지막 라운드는 고칠 것을 남기지 않았습니다.

- **Windows 에서 세 테스트가 깨질 뻔했습니다.** 메시지에 찍는 경로를
  `os.path.join` 으로 만들어서 Windows 에서는 역슬래시가 나왔습니다. 메시지용
  상수는 `/` 로 고정하고 디스크 경로만 따로 만듭니다.
- **이 스크립트를 처음 실제로 돌리는 릴리스 커밋이 자기 테스트를 깨뜨릴 뻔
  했습니다.** 이 작업 항목이 조각을 썼는지 확인하는 테스트가 조각 파일의
  존재를 단정했는데, 접기가 그 파일을 지웁니다. 접힌 뒤에는 `map.md` 의
  표시로 확인하도록 바꿨고, 그 수정에 딸린 테스트가 다시 같은 모양으로
  깨지는 것을 2 라운드가 잡아 픽스처 위에서 접도록 고쳤습니다.
- 그 밖에 산문에 인용된 표시 문자열이 접기를 거부하던 것, U+2028 같은 줄
  구분 문자가 파일을 조용히 닫던 것, 행이 바이트 그대로 옮겨지지 않는 모양
  셋(꼬리 공백, U+2028, 펜스 안의 `#`)을 고쳤습니다.

## 남겨 둔 결정

`questions.md` 의 셋은 기본값으로 진행했고, 저장소 소유자가 뒤집을 수 있습니다.

- Q1. 이전 릴리스 항목의 안 비운 `evidence-todo.md` 도 이번 릴리스를 막는다
  (트리에 있는 것은 전부 읽는다).
- Q2. 접힌 절은 `map.md` 끝에 덧붙인다. 대조표는 영역과 좌표로 읽고 검사기는
  위치를 읽지 않는다.
- Q3. `--check` 는 남은 조각뿐 아니라 열린 행도 본다.

펜스 닫힘 규칙이 CommonMark 보다 느슨한 것은 오늘의 조각에 해당 형태가 없어
코드 옆 `# RIDER:` 주석으로 남겼습니다.

## 운영에 영향을 주는 것

릴리스 준비 순서가 한 줄 늘어납니다. `gather_changelog.py --version` 옆에서
`fold_ledger.py --version X.Y.Z` 를 돌립니다. `docs/branch-and-release.md` 와
`CONTRIBUTING.md` 의 릴리스 절차에 적혀 있습니다. 새 의존성은 없습니다.
