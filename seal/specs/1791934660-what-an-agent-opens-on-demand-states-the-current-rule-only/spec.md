## What this set needs that the preload set did not

**The criterion, applied to a skill.** A skill is read by an agent mid-run to do an act, so the act's steps, the format it writes, the vocabulary a checker reads, the known limits and the promises other parties rely on are contract and stay with `Enforced by:`. What a script does inside — the arms `broad_gate.py` runs and how each errs, the invariant `session_cost.py` applies, what `round_record.py close` derives from a range, the refusal texts of `budget_check.py`, the mode gate's reading — is mechanics: its home is the first sentence of the test that holds it or the unit's docstring, and the skill keeps one sentence naming the command and linking the home. The measured proxy puts 37 % of `skills/verify/SKILL.md`'s paragraph bytes, 39 % of `skills/code-review/orchestration.md`'s and 20–22 % of `skills/implement/orchestration.md`'s and `templates/config.md`'s in that class; each phase partitions its file rule by rule first and records the sum before it rewrites.

**A template's content is its comments, and a comment is a rule for the cell it sits in.** The shape for a template: the format kept whole (rows, headings, markers, the fence a generator parses); one comment per cell or section of at most three live lines — what goes in the cell, the vocabulary a checker reads, and the link to the rule's home; no story. `templates/sdd-routing.md` is the one whose saving is paid per work item.

**The orchestrator is a reader with no agent, so its files get cases of their own.** `skills/implement/orchestration.md` §*Orchestrator: which of these acts runs itself* maps every marked act to what notices when it is forgotten. An act with `check:` or `command:` is held by that check — a rewrite that drops its sentence is noticed by the same thing that notices the orchestrator forgetting it, and the census row says `held by: <path>`. The five `still a sentence` acts and the routing act's un-checked half (question 1 alone, before the first edit) get a rule-exercise case each under `evals/behaviour/orchestrator/` (below); the session under eval is the orchestrator reading the target tree's `orchestration.md`, so old tree against new on the same cases is #923's comparison with `orchestrator` as a fifth agent name, its baseline taken once against the merge base's plugin tree. Acts no fixture can reach — the pull request opened before round 1 (needs GitHub), closing the cycle, a fix pass resumed into a live agent — are census rows `not exercisable — <why>` held by their `check:` rows.

**The proof's cadence** (the owner, 2026-10-14): each phase runs the behaviour cases mapped to the rules it changed, and each agent's full suite — the orchestrator's included — runs once at the item's end. The census per phase maps each of the file's rules to `Exercised by: <case>/<grader>`, `held by: <check or test>` or `not exercisable — <why>`; the record test refuses a row with none (#923 S13).
