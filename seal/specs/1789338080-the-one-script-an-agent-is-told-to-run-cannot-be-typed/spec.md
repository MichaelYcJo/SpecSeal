# Feature Specification: the one script an agent is told to run cannot be typed

#318 reports one symptom — four agent segments concluded
`skills/code-review/scripts/round_record.py` does not ship, and hand-wrote the
record `chain_check.py` parses — and proposes two fixes without choosing
between them. **The choice is a false one, and that is this frame's main
finding.** The two fixes repair different halves of the defect, and either one
alone leaves the other half standing.

- **The typing half.** Two places in `skills/code-review/orchestration.md`
  show a command for somebody to run, and both spell it `round_record.py
  <subcommand>`, which resolves nowhere. A `bin/` wrapper is what fixes that,
  because every sibling checker is already reachable that way.
- **The looking half.** The other thirty-four mentions across nine shipped
  documents describe what the generator does — *`round_record.py new` writes
  `round-N.md`* — and a reader who goes looking for that filename finds
  nothing, because **no shipped document anywhere names a path to it.** A
  wrapper does not repair this: the reader was never going to type a command,
  they were going to open a file.

The looking half is the one the incident actually exercised. Three of the four
segments were `warden`, and `agents/warden.md` never tells the warden to run
the script at all — all five of its mentions say the opposite, that the record
is written for it. Those segments went looking and concluded absence.

drawn against: the finding names a coordinate and the fix is owed to the class.

## The name is not this frame's invention

**Executed** 2026-09-14: `python3 skills/code-review/scripts/round_record.py
--help` exits 0 and its first line reads `usage: round-record [-h]
{new,close,seal} ...`. The script already calls itself `round-record`, in the
hyphenated form every sibling wrapper uses. The wrapper is not a new command
being designed here; it is a command the script has been announcing since it
shipped, for which no file was ever written.

## Scope

### In

1. **`bin/round-record` and `bin/round-record.cmd`**, modelled line for line on
   `bin/survivor-check` and its twin — the nearest sibling, same skill, same
   `skills/code-review/scripts/` target.
2. **The two typed command forms** in `skills/code-review/orchestration.md`
   become `round-record …`, which is how `survivor-check` and `broad-gate` are
   already spelled where a document shows a command.
3. **Every shipped document that names `round_record.py` also names a way to
   reach it** — the `round-record` command, or the script's repo-relative path
   — at least once. Nine documents, listed in the table above. The wording and
   placement are the builder's; the property is what this spec fixes.
4. **The class, pinned.** One new test file that enumerates every
   `skills/*/scripts/*.py`, requires a `bin/` wrapper pair for each one a
   shipped document names, and requires each such document to carry a
   reachable form. A script with no wrapper is classified in the test with its
   reason, so the next one is a decision somebody records rather than a gap
   somebody notices.
5. **`chain_check.py` classified, and the classification defended.** It has no
   wrapper and keeps none (see Out). The pin asserts the property that makes
   that safe: **no shipped document shows it in command form.** Verified
   **executed** 2026-09-14 — `grep -rn 'chain_check\.py -' --include='*.md'
   agents/ skills/ templates/` returns nothing, exit 1.
6. The changelog and ledger fragments for this directory.

### Out, and why

- **A `bin/chain-check` wrapper.** `chain_check.py` is named 23 times in
  shipped documents and **never with a flag**; the five places that invoke it
  — `.github/workflows/hygiene.yml`, `templates/hygiene.yml`,
  `docs/release-checklist.md:100`, `skills/verify/scripts/broad_gate.py` and
  `skills/code-review/scripts/round_record.py` — all reach it by full path, so
  it is reachable everywhere it is reached. Wrapping it would widen this branch into a file no
  other work item in 0.11.4 opens, and `templates/config.md` spells
  `chain_check.py` to users in the row that configures the broad gate, which is
  a user-facing change with no defect behind it. It is classified in the pin
  instead, which leaves a written decision where there is currently nothing.

## Failure direction and prompt budget

`CONTRIBUTING.md` asks both of a change that touches a gate, and the suite is a
gate on every pull request.

- **Direction: blocks more.** A shipped document that names a script with no
  reachable form now fails CI. That is the cheaper mistake here. A wrong deny
  costs one sentence, written by the person who is already editing that
  document. The wrong allow it replaces is the measured incident: four agent
  segments, four hand-written records, and two fields wrong in ways only the
  next round's reader caught — which #318 correctly calls luck rather than a
  gate.
- **Prompt budget: zero.** Nothing in this change puts a question in front of
  anybody, in a session or in CI. The pin fails with the sentence to add.
- **Platform honesty.** The `.cmd` twin's behaviour is asserted by constructing
  the command both ways from either machine, the way the sealer's module
  already does, so a wrong wrapper fails locally rather than only on the
  Windows runner. No claim is made here about a Windows run that nobody took.
