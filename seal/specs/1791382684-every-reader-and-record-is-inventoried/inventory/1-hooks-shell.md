## Observations

- **Class split.** 101 of the 144 rows are `guess`, 25 `observed`, 18 `owned`. Every reader of shell text is `guess` except one: `oh` (row 55) is a closed grammar this repository defines. It admits one shape and returns None for everything else (oh:12-14). The `observed` rows are git plumbing, `ps`, `/proc`, `os.kill`, and the harness payload.
- **Two generations of the shell reader run on every guard call.** `cb` is cl as of `86256492`. By syntax tree, 54 of their top-level definitions and constants are identical, 12 differ (10 functions, plus `RUNNERS` and `STRING_HOSTS`), and 28 exist only in cl. The guard reads each command through both: `import cmdline_base as cmdline` (wg:150) and `import cmdline as wide` (wg:170). Eleven cb functions have no production caller (row 49) but stay, because the test pins the whole file (cb:17-19).
- **The two parsers find different subcommands.** cb's `_git_options` takes 6 value options and cl's takes 9 (cb:2176 vs cl:2979-2989). So the frozen `parse_git` reads `git --config-env a=B switch x` as subcommand `a=B`, while the commit gate's reader reads `switch` (read, not run).
- **The guard and the consent writer can pick different directories for the same creation** (executed probe, row 127). The guard takes `wheres[0]` and falls back to cwd when it is unresolved (wg:2998, wg:631). The writer takes the first resolved entry (wc:448-451). For `eval x ; cd /tmp/a || git worktree add ../wt f`, the guard judges `/tmp/S` and the writer records consent under `/tmp/a`'s clone.
- **Three readers of one waiver vocabulary, and one of them behaves differently.** `tk.given` (tk:83), `crg.has_marker` (crg:657) and `wg.has_token` (wg:381) each use a different splitter. Only `has_marker` falls back to a substring test when the command does not split (crg:695-696). The git-native path reads the same token through `tk.given` via `answers.py`, which refuses instead.
- **Copied judgments.** Three wrappers of `automation_answered` (cg:88, crg:862, wg:2550). Two copies of the eval reader (crg:243, wg:2293). Two `already_asked`: crg:700 uses `--git-dir`, wg:1515 uses `--absolute-git-dir`. `crg.git`, `crg.read_mark` and `crg.declaration_hint` repeat gt:65, gt:81 and gt:134. `crg.read_mark` (crg:586) and `crg.is_git_commit` (crg:494) have no caller anywhere.
- **Parallel models of the same shell facts.** Redirections: cl `_REDIRECTION` (cl:48), wg `_OPERATORS`/`_plain_words` (wg:2155), and tk `is_plain`'s own test (tk:243). Where a heredoc body ends: cl:388, cl:2148, oh:66, plus a marker regex at tk:223. Lexers: three shlex setups (tk:47, tk:226, cl:674), plus Windows backslash doubling on top (wg:274).
- **Two measured allowlists of git subcommands, built the same way.** Both come from counts over the recorded-transcript corpus: tk `PLAIN_GIT` has 7 (tk:170, 2026-10-02) and wg `LEAVES_THE_TREE` has 49 (wg:2048, corpus up to 2026-10-06). Each says the list grows only by measured rows.
- **A failed git call turns into "no change".** `gate.git` and `crg.git` return "" on a non-zero exit (gt:78, crg:581). `touches_code([])` is then False, so the parity arm goes silent.
