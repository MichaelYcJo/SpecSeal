## Observations

- **The commits since v0.18.0 landed in the writer and the pact readers, not in the extractors.** `evidence_check.py` had 7 commits v0.18.0..HEAD (#756; #771; #774/#772/#775; #759; #785/#792/#781; #822; #824/#806/#809) and grew by 1410 lines. All of them touch `--reverify`/`--into`/the pact record (E45–E55) or the pact-row reader (E51, E52). `pact_check.py` had 2 (#756, #822) and `settle.py` 2 (#768, #770). `correction_check.py`, `fold_check.py` and `seal.py` had none.
- **One coordinate grammar is written five times, and the copies disagree:** `ANCHOR_RE` (E L146), `correction_check.ANCHOR` (C L427) and `CITATION` (C L580), `settle.COORDINATE_RE` (S L196), and `.github/scripts/rider_check.py:159`. C3 requires a dotted path and takes `@hex{6,}` with no upper bound. A row the checker grades may therefore have no identity for `correction-check`.
- **Readers of `seal/config.md` pick between duplicate rows differently.** `frozen_from` (E L3880) and `cutoff_at` (C L935) take the last matching row. `fold_check.row_value` (F L509) takes the first, and `seal.table_span` (X L1461) writes the first, saying that `config_rows` "reads the first". `config_rows` returns every row; each caller chooses.
- **The same file gets four answers when it cannot be read.** An unreadable `config.md` turns the freeze off (E47, C17), reads as "nothing declared" at exit 0 in fold-check (F11), makes `record_pact_changes` refuse (E54, L4617), and is UNREADABLE at exit 2 in pact-check (P L586).
- **Every non-Python language goes through one indentation regex** (E17 L743, copied at E18 L943). The probe found units that never resolve: Go receiver methods, Rust `fn f<T>`, Java `List<String> f(`, and any `Class.method` outside `.py`. For C with the brace on the next line, the span is the signature line alone, so edits to the body read OK in silence. In a user's repository these anchors are someone else's format, read as a guess.
- **The Python path is observed, but only for the running interpreter's grammar** (E12). A SyntaxError, including newer syntax, silently falls to the E17 guess. `.pyi`, `.markdown` and `.mdx` take the generic rule because the dispatch is by suffix, spelled four times (E16).
- **Four definitions of a markdown heading:** `heading_level` (E L517), `GITHUB_HEADING_RE` + setext (E L5186), `fold_check.HEADING` (F L139), and `startswith("## ")` (S L407). The probe shows `heading_level` misses a heading indented 1–3 spaces and counts a `## B` inside a closed fence as a heading, so a unique heading reads as ambiguous (BROKEN).
- **"Is this line live" has four rules in this part:** `quoted_lines` (HTML comments read), `unverified_check.live_lines` (comments not live, used by S7 and F3), `claim_lines` (its own fence and comment state machine), and `anchored_rows` (every line). The settle docstring (L600–611) states that bias on purpose.
- **Readers that guess from a person's prose:** E30 (Code grounds words), P10 (`pact:` mentions), E51/E52 (anything that could name a pact), C2/E35 (correction markers), E58–E61 (record claims, GitHub slugs), S10/S12/S14/S16, F7 (bold opening), X24 (URL substring).
