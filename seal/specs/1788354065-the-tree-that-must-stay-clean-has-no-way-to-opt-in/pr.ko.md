## 무엇이 달라지는가

훅이 읽는 옵트인 신호는 커밋된 `seal/` 하나뿐이었습니다. 회사 저장소처럼 자기
규약이 있는 곳이나 남의 프로젝트에 기여할 때는 그 디렉터리를 커밋할 수 없고, 그러면
게이트도 리뷰 체인도 전부 꺼져 있었습니다. gitignore 로 두는 것은 답이 아닙니다.
연결된 worktree 는 커밋된 파일만 체크아웃하므로 무시된 폴더는 어느 worktree 에도
없고, `.specseal/` 을 무시했을 때 병렬 세션이 서로의 기록을 못 읽은 것이 바로 그
이유였습니다.

이제 루트가 놓일 자리가 둘이고, 훅은 폴더가 어디 있는지로 모드를 읽습니다. 설정
키는 없습니다.

1. **local 모드는 루트 전체를 `$(git rev-parse --git-common-dir)/seal/` 에 둡니다.**
   메인 트리에서는 `.git/seal/` 이고, 그 저장소의 모든 연결 worktree 가 같은
   디렉터리를 봅니다. 그 아래는 커밋 후보가 될 수 없어 `.gitignore` 줄도 필요
   없습니다. 읽는 쪽은 0.4.0 부터 있었고, 이번에는 루트 아래로 경로를 잇던 훅과
   스크립트 전부가 그 자리에서 찾도록 바꿨습니다. 근거 조언 훅, 대조표 이관 훅,
   커밋 게이트의 안내 경로, 검사기의 기본 경로, 이관 훅의 완료 표시 규칙입니다.
2. **첫 설정이 질문 하나를 한 번 합니다.** `implement` 스킬이 루트를 만드는
   순간에 shared 인지 local 인지 묻습니다. shared 가 먼저이고 기본값이며, 두
   선택지 모두 무엇을 만들고 무엇을 설치하는지 적혀 있습니다. 어느 자리든 이미
   `seal/` 이 있는 저장소에는 다시 묻지 않습니다. 패리티 질문은 그 뒤에 지금처럼
   옵니다.
3. **shared 모드는 PR 검사를 템플릿으로 설치합니다.** `templates/hygiene.yml` 은
   플러그인을 릴리스 태그로 러너의 임시 디렉터리에 받아, 미확인 기록 검사와 리뷰
   체인 검사를 사용자 저장소에 대해 돌립니다. `.github/workflows/hygiene.yml` 이
   없을 때만 씁니다. local 모드는 아무것도 설치하지 않고, 템플릿 머리말에 이유가
   적혀 있습니다. 그 검사들은 커밋된 파일을 읽으므로 local 모드에서는 아무것도 안
   본 채 초록이 됩니다.
4. **모드 전환은 문서로만 안내합니다.** README 두 벌과 루트의 README 에 두
   방향의 이동 명령이 있고, 저장소 루트를 `git rev-parse --show-toplevel` 과
   `--git-common-dir` 로 잡아 어디서 실행해도 같은 자리에 놓입니다. local 루트를
   내보내고 들여오는 것은 #81 입니다.

## 리뷰에서 나온 것

두 라운드를 돌았고 둘째 라운드는 고칠 것을 열지 않았습니다. 첫 라운드는 커밋
게이트의 새 안내 경로가 판정보다 먼저 상대 경로를 계산하는데, Windows 에서 다른
드라이브의 연결 worktree 를 만나면 그 계산이 예외를 던지고, 훅 실행기가 예외를
승인으로 읽어 커밋이 판정 없이 통과하는 것을 찾았습니다. 같은 호출이 대조표 이관
훅의 변경 여부 검사에도 있었습니다. 둘 다 막았고, CI 의 Windows 레그에는 드라이브
둘짜리 배치가 없으므로 어느 플랫폼에서든 그 예외를 일으켜 확인하는 테스트로
고정했습니다. 같은 라운드에서 전환 명령을 하위 디렉터리에서 실행하면 저장소가
옵트아웃되는 것과, 첫 설정 안내가 세션이 볼 수 없는 파일을 경로 없이 이름만 대는
것도 나왔습니다.

## 결정을 남겨 둔 것

`questions.md` 의 Q1–Q9 는 기본값으로 진행했습니다. 세션은 `implement` 스킬과 두
에이전트에 적힌 한 문장으로 local 루트를 찾고, 검사기의 플러그인 사본은 리졸버를
불러오되 배포된 사본은 트리를 읽으며, 이관 훅은 어느 자리든 `seal/` 이 있으면 완료
표시를 남기고, 템플릿은 플러그인 태그를 고정하고, 게이트 안내는 찾은 루트 아래
경로를 말하고, shared 선택지는 라우팅 커밋이 폴더를 실어 나른다고 적고, 옮기지 않은
0.3.x 배치에는 묻지 않고 훅이 먼저 옮기며, 설계 기록의 낡은 두 문장은 제자리에서
고쳤고, `actions/checkout` 은 작업 공간 밖을 체크아웃하지 못하므로 템플릿은
`git clone --branch` 로 받습니다. 기본값을 고를 수 없던 질문이 하나 있습니다.
`CLAUDE.md` 는 변경이 앵커를 없앤 행은 지운다고 하지만, 앵커 여섯 중 하나만 없어진
행은 말하지 않습니다. 이번에는 그 행을 지우고 남은 다섯 주장을 새 조각 행으로
썼습니다. 규칙에 그 경우를 적을지는 결정해 주셔야 합니다.

## 운영에 영향을 주는 것

묻지 않고 트리에 쓰는 것은 없습니다. 첫 설정에서 질문이 하나 늘고, 저장소당 한
번입니다. 어느 자리든 `seal/` 이 있으면 묻지 않습니다. shared 모드는 첫 설정 때
워크플로 파일 하나를 없을 때만 씁니다.

Windows 레그가 돕니다). 실제 shared 모드 러너에서의 템플릿(첫 사용자 저장소의 CI 가
