## Summary

Nineteen `docs/` files are rewritten to #923's compact shape, one file or one coupled cluster per phase, the three files at the 1,000-line ceiling first. Phase 1 proves the whole procedure on `docs/worktree-guard-spec.md`, the file with the most narrative (463 lines in paragraphs that open with no rule) and the most released ledger rows (79): before and after numbers, every row read one at a time, every pin and link answered, the census. Each later phase repeats it on its files and adds the eval record where an agent case opens them. Headings stay, so the 391 released anchors drift rather than break; a heading that is itself history leaves with its section and its rows are corrected by hand. The item adds no check, script or test: the check is #923's phase 1 in #930's checker, the proof is #923's phase 2 harness, and this branch waits on both (§*Dependency*).

**What breaks in 6 months with the chosen approach.** A `settle` fold appends rule paragraphs to a compacted doc at release, and `bytes:<docs file>` then fails the release pull request unless its body carries a `Budget raised:` line nobody's step writes (Q1, #923's smith). Headings kept for the anchors' sake leave an outline shaped by the old file where a section is now one paragraph; the cost is a heading per coordinate, and the next fold's placement rule reads headings, so it is also what keeps folds landing where they did. The Korean edition drifts sentence by sentence under a check that reads outline and markers only; that is today's state, not a new one. Narrative grows back inside fold statements that carry stories: `history:` 0 catches the marked lines, the eight-line bar is review's. A rewrite satisfies `history:` by deleting the issue number and `bytes:` by cutting a rule for a story: the census, the pins and the ledger rows are the three readers, and the suite where a case opens the file.

**How a cut is shown not to lose a rule somebody needed.** Four readers per file, none a person: the census (every bold-led rule → a coordinate or a `## Removes` row, each `Exercised by:` or `not exercisable — <why>` naming the tests that hold it); the ledger (every released row read, a claim the new text no longer holds being a `Corrected ·` row somebody has to write); the pins (every module green on the new sentence or its literal dropped with a row); the suite where an agent case opens the file (phases 2–5, 7, 9), with #923's pass rule 4 naming a rule grader every old run satisfied and no new run did. The remaining gap is a rule in one of the ten files no case opens whose test pins narrative rather than the rule; the census row names the test, and review reads the list.

**Cost.** CI: no new job, step or dependency; the budget rows ride #930's hygiene step and the suite case, and the pin modules this item edits run in the suite as they do today — zero added minutes on any leg, private or not. Eval runs, on the orchestrator's account and never in CI (estimated from #923's run medians, nothing has run): three warden phases at ≈ 16 runs and ≈ 1 h each at `-j 4`, three smith phases at ≈ 8 runs, one sealer at ≈ 6, about 78 runs and ≈ 4 h of wall clock over the item (Q5).
