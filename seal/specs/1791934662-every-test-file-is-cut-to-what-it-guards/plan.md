## Summary

One pull request per shipped module. For a module whose files are heavy or redundant: the old files' killed-mutant set and real-bug regressions are taken once as baseline and reference, tangled decisions are extracted into pure functions, the tests are written again per unit — a decision table and one end-to-end case per real path — shown to kill every baseline mutant, and the old content is deleted at the same path, recorded in one summary line. For a module whose files are fast and thin: #929's per-case cut. Every batch lowers its rows and commits its run's durations union; no pull request runs the regrowth check over 5 minutes or slows any `pytest` job, and the slowest job reaches 5 minutes at the item's end. Released ledger rows citing deleted ids are one named step per batch, per the owner's pending decision. Heavy modules go first, after one small module proves the shape.

**What breaks in 6 months with the chosen approach.** The baseline is only as wide as the battery: a sentence no old case named is not in it, a new file that drops the old case guarding it passes non-inferiority, and the gap arrives as a bug; the port list is the guard for the known shapes and nothing guards an unnamed one. Second, an extracted pure function is tested by its table and the thin caller by one end-to-end case; a bug in the caller's wiring that the one path does not cross is unseen, which is the trade the owner chose over a repository per case. Third, `slowest-job` is a one-sided row read from a run, so a slow runner raises it until somebody reads the run; #930's `ci-minutes:*` already carry that.

## Operational impact

- One row (`slowest-job`) and its measurer in `budget_check.py`; pure functions extracted in the modules `spec.md` names, each with a `Reads:` line; no new dependency, job or file. `.test_durations` is replaced per pull request from the run's artifact, never by hand.
- Every pull request: regrowth check ≤ 5 min, no `pytest` job slower than the last; the rows say so and fail otherwise.
- What a batch deletes is one summary line in the changelog fragment or the phase record; `Enforced by:` lines in prose files are re-pointed in place; released ledger rows citing deleted ids wait on the owner's decision and are named, not touched.
- **Process hygiene, binding on every agent this run spawns.** Clean up only processes you started: hold the PIDs of what you launch (`subprocess.Popen` objects, `$!`) and end those; never `ps | grep mutation_check | kill` or any match on a command name, because another agent's run matches the same name — this frame's framer killed #929's smith's `mutation_check.py` that way on 2026-10-14. A hung battery run is ended by its own PID, and the module is then read by `git status` and restored from the commit if the tool's restore did not run.
- A mutant battery run is bounded by `--timeout` on every call; a run that is ended from outside leaves the shipped file mutated until restored (§7).
