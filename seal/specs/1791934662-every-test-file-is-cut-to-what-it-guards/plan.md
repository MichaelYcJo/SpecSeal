## Summary

Batches by the module a file loads, one pull request each, biggest proven win first after one small batch proves the shape. Each batch: the module's mutation battery over every file that loads it, before and after; removals within each file where the table shows the file still kills without the case; one case where a sentence survives; a `Kills:` line on every kept function; the files off `tests/unguarded-files.txt`; the rows lowered and the run's `.test_durations` union committed; the ledger and `Enforced by:` lines re-pointed. Fourteen files whose proof alone costs 30 minutes to 6½ hours of ubuntu under #929's two-run check are one phase of their own, placed by the owner (`questions.md` Q1).

**What breaks in 6 months with the chosen approach.** The battery is drawn from what the kept files say they guard, so a sentence no file names is never mutated and its first mutation arrives as a bug; the `unguarded-files` row at 0 then reads as "every sentence guarded", which it does not mean. Second, the fourteen heavy files sit in phase 10 and the row sits at 14 the way `undeclared_readers.txt` sat, trimmed by one a release. Third, a `Kills:` line on a prose pin goes stale when #923 moves the sentence, and nothing reads it until the function is next changed; `case_check.py` reads the list's files whole for presence, not for landing.

## Alternatives considered

| Approach | Failure scenario (six months on) | Verdict |
|---|---|---|
| A. Batches by the module a file loads; one pull request each; the battery run over the module's files; removal within a file by #929's criterion; heavy files in one phase of their own | above | **chosen** |
| B. Batches by fixture family (the files sharing `repo`, `run_hook`, a `git init` body) | a battery is drawn per unit under test, and the fixture-mates load different units; a survivor in one is judged against the other's cases, never run; redundancy across modules is judged, which #929 alternative I refuses | rejected |
| C. Batches by size, one file per pull request, largest first | the file's battery has 4–5 survivors in 8 (`spec.md`'s sample) that a sibling file kills; each phase plants a case the sibling already has, and the suite grows by what the table could not see | rejected alone; size orders the files inside a family |
| D. One pull request for the 180 files | 142,559 lines of diff no round reads whole; one finding reopens every file; the `cases` job runs 2,082 minutes on one pull request | rejected |
| E. Every file in 0.22.0 whatever the proof costs | the heavy pull requests wait 0.5–6.5 h on the `cases` job each, or the job is waived "this once" and #929's gate gains a waiver that becomes the habit | rejected; phase 10 and Q1 |
| F. `Kills:` lines on this item's own functions only; prose pins left bare | 100-odd mixed files never leave the list, and `unguarded-files` sits at its ceiling the way the docs sat at 1,000 lines | rejected; the line names the document, #929 S5 |
| G. The tail to 0.22.1 whole | 0.22.0 ships the mechanism with 175 files exempt and nothing moves the list; #929's own third failure scenario | rejected |
| H. Removal by line coverage (`coverage.py`) | a covered line is not a guarded sentence; a case can execute every line and assert nothing, and 24 do | rejected |

## Operational impact

- No new script, job, dependency or file; one list shrinks, one budgets file's ceilings fall, one durations file is replaced per cut pull request from the run's artifact, never by hand.
- Every pull request here lines every function it keeps, so #929's `cases` job runs 1 + 2N times per touched file on it; the batches are sized to keep that under the Windows leg's wait, and phase 10's files are the ones that cannot be.
- Released ledger rows citing removed or changed cases are answered in the fragment, never edited; `Enforced by:` lines in `docs/` are re-pointed in place.
- A prose-pinning case gains a `Kills:` line and nothing else; #923's phases re-point the line when they move the sentence.
