**대조표의 행은 위치가 아니라 내용을 가리킵니다.** `경로#단위@해시` — 감싸는

자기가 쓰지 않은 줄 번호를 믿기 전에 옛 스탬프의 커밋을 확인하는 일회성

**두 브랜치가 같은 파일을 쓰지 않습니다.** 변경 이력은
`specs/<work-item-id>/changelog.md` 로 가서 릴리스 때 모이고, 대조표 행은
`.specseal/map/<work-item-id>.md` 로 가서 영원히 모이지 않습니다. work item id
는 겹치지 않으므로, 가장 나쁜 순간 — 넓은 게이트가 이미 돈 뒤라 다시 돌려야
하는 시점 — 의 충돌이 사라집니다.

하는가, 그리고 알린 뒤 저장된 좌표가 여전히 옳은 자리를 가리키는가. 구현자와
독립적으로 리뷰 오케스트레이터가 돌렸고, 전체 기록은 `ab-comparison.md` 에

**3/7 → 6/7.** 유일한 실패는 의도한 것입니다. 공백만 바꾼 재정렬과 뜻이 바뀌는
들여쓰기 변경은 파서 없이 구별할 수 없고, 이 설계는 들여쓰기를 해시에
남깁니다 — 재정렬에는 시끄럽고, 문장이 루프 밖으로 나갔을 때는 옳습니다.
처방은 `evidence-check --reverify .` 한 줄입니다.

검사기 실측, 다섯 번의 중앙값: **356 ms → 약 130 ms**, git 호출 없음.

## 묻지 않고 바뀌는 동작 둘

둘 다 사람에게 질문을 하지 않습니다. 그게 요점이자 위험이라 여기 적습니다.

1. **옛 형식 대조표가 시끄럽게 실패합니다.** `경로:줄` 행으로 찬 대조표가
   예전에는 `0 ok · 0 drifted · 0 broken`, exit 0 으로 읽혔습니다 — 업데이트한
   사용자의 커버리지 전체가 한 글자도 없이 사라진 것입니다. 이제 합계 줄과
   커밋 권고 양쪽에서 `OLD-FORMAT` 을 내고 0 이 아닌 코드로 끝납니다.
2. **옵트인한 저장소가 세션 시작 때 대조표를 옮깁니다.** 저장소당 한 번,
   깨끗한 트리에서만 — 그래서 모든 쓰기가 커밋된 기준선 위에 놓입니다. 옛
   스탬프 이후 인용 줄이 바뀐 행은 추측하지 않고 남깁니다. 약 24 ms.

## 이행 경로

`evidence-check --migrate .` 가 `경로:줄` 대조표를 제자리에서 변환합니다. git
이 답할 수 있는 곳에서는 각 행의 인용 범위를 옛 스탬프의 커밋과 대조하고,
그 사이에 바뀐 것은 **남깁니다.** 그 증명 없이 다시 쓴 행은 소리 내어
셉니다. `--map` 과 `--default-repo` 를 읽으므로 다른 저장소를 인용하는
마이그레이션 대조표도 변환됩니다. 세션 시작 훅이 같은 코드를 돌리므로 대부분의
저장소는 이 명령을 칠 일이 없습니다.

**`.specseal/` 를 지우는 것은 이행 경로가 아닙니다.** 그 디렉터리가 옵트인
신호 자체라서, 지우면 모든 게이트가 조용히 꺼지고 사람이 읽어서 확인한 행이
전부 버려집니다. 정책에 그렇게 적었습니다.

## 하드닝

`place()` 가 배치된 체크아웃 밖으로 풀리는 좌표를 거부합니다. 루트 위를
가리키는 상대 경로 행이 예전에는 읽혔고, `--reverify` 가 읽은 내용의 해시를
대조표에 써 넣었습니다. 릴리스된 0.1.0 검사기에도 같은 구멍이 있으므로 회귀
수정이 아니라 새 가드입니다. 버전 대응은 draft advisory 가 들고 있고 릴리스
때 공개됩니다.

그리고 이번에 배운 것 하나 — **확립하지 않은 통과를 보고하는 검사는 정확성
결함이 아니라 보안 결함입니다.** `tests/test_gates_do_not_fail_open.py` 가
대조표 reader 까지 덮습니다. 읽을 수 없는 파일이 빈 파일과 구별되지 않고
exit 0 이던 자리입니다.
