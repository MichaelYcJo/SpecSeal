# `user-invocable: false` 를 단 스킬은 subagent 에 preload 되지 않는가,
# 그리고 설치본 중 실제로 로드되는 사본은 어느 것인가

2026-09-03, Claude Code 2.1.259 에서 #107 의 Q1 을 위해 쟀습니다. 아직
릴리스하지 않은 변경을 시험하려면 어느 사본을 고쳐야 하는지도 이 실험이
결정했습니다.

## 질문

#107 은 모든 에이전트가 따르는 규칙을 파일 하나에 두고, 오케스트레이터가
매번 다시 타이핑하지 않아도 에이전트가 받게 하려는 작업입니다. 이미 쓰이고
있는 메커니즘은 에이전트 frontmatter 의 `skills:` 입니다. 거기 적힌 스킬은
에이전트가 시작할 때 본문 전체가 주입됩니다. 그런데 그렇게 하면 그 스킬이
사용자의 `/` 메뉴에 명령처럼 뜹니다. 숨기는 방법으로 문서가 제시하는 것은
`user-invocable: false` 이고, preload 를 막는 쪽은 *다른* 플래그인
`disable-model-invocation` 이라고 문서는 말합니다. 이 저장소에서 두 가지를
같이 써 본 적이 없어서, 숨긴 스킬이 에이전트에 닿는지는 사실이 아니라
읽은 것에 불과했습니다.

## 확정된 것

1. **`user-invocable: false` 는 preload 를 막지 않습니다.** 플래그를 단
   스킬이 본문 전체와 함께 스폰된 에이전트에 닿았고, 에이전트는 그 스킬을
   이름으로 나열했습니다.
2. **로드되는 사본은 버전별 캐시입니다.**
   `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/` 입니다.
   작업 트리가 아니고, `~/.claude/plugins/marketplaces/` 아래의 마켓플레이스
   클론도 아닙니다. 클론은 설치할 때 캐시로 복사되는 원본일 뿐입니다. 세
   번은 클론을 고쳤는데 아무것도 읽지 않았습니다. 이 저장소에서 고친 규칙은
   릴리스를 태그하고, 플러그인을 갱신하고, 캐시를 새로 읽기 전까지는 어떤
   세션에도 적용되지 않습니다.
3. **preload 되는 스킬 본문은 세션 시작 때와 `/reload-plugins` 때 읽히고,
   스폰 때는 읽히지 않습니다.** 문서의 *"`SKILL.md` 텍스트 변경은 실시간
   감지된다"* 는 메인 세션이 스킬을 그때그때 불러올 때의 이야기입니다.
   subagent 가 받는 것은 마지막 리로드 때 읽어 둔 본문입니다.
4. **26 KB 짜리 본문도 통째로 들어갑니다.** 에이전트가 요청에 따라 본문
   마지막 줄을 그대로 인용했으므로, 긴 파일 끝에 둔 센티널이 잘려서 빠진
   것은 아닙니다.

## 방법

에이전트가 이미 preload 하는 스킬을 하나 고릅니다. `agents/smith.md` 의
`skills:` 에 있는 `writing-style` 입니다. 그 frontmatter 에
`user-invocable: false` 를 더하고 본문에 센티널 한 줄을 넣습니다. 모든
도구를 금지하고 질문 하나만 던지는 프롬프트로 `specseal:smith` 를
스폰합니다. *시작할 때 받은 텍스트에 이 센티널이 있는가.* 답을 읽습니다.
고치기 전에 받아 둔 백업으로 파일을 원복하고, 클론과 바이트 단위로 같은지
확인합니다.

한 회차에 약 3 초, 61k 토큰이 들었습니다. 여섯 번이 필요했던 이유는 앞의
네 번이 엉뚱한 사본을 고쳤기 때문입니다.

## 확정되지 않은 것

사용자의 `/` 메뉴에서 플래그를 단 스킬이 실제로 빠지는지는 재지
않았습니다. 그것은 문서에 적힌 동작이고, 결정에 걸려 있지도 않습니다.
메뉴에 보이더라도 대가는 아무도 실행하면 안 되는 항목 하나이지, 계약이
도착하지 않는 것이 아닙니다.
